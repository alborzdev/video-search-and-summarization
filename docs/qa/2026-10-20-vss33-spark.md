## Resource and data constraints

ACT training remains independent and must not be interrupted. Spark's selected **20 GiB available-memory reserve** stays active through the user unit `vss-spark-guard.service`. Model/KV budgets are unchanged. The GB10 reports unified memory; host available memory and guard telemetry are the admission evidence, rather than an unavailable per-process VRAM total.

Non-VSS infrastructure versions remain on the previously cached PostgreSQL, Elasticsearch/Kibana, Redis, Kafka and monitoring images. This avoids a persistent database-format migration during an application feature update. GPU driver 580.142 is unchanged; NVIDIA documents a later Spark driver for 3.3, so successful bounded tests cannot establish blanket hardware support.

## Cleanup and reliability fixes

Removed superseded agent layouts, obsolete deployment skill paths, the stale 3.2 image inventory mirror, the broken legacy RTVI manual client, unused UI screens/helpers and duplicate tests that asserted unsafe lifecycle behavior. Useful replacement ownership, cancellation and stream-isolation coverage remains. NVIDIA's upstream removal of vendored VIOS/WebRTC headers accounts for most of the large merge deletion count; it is not an application speed benchmark.

Fixed shared-subscriber abort lookup, callback-drain accounting and a concurrent decoder-boundary race. Request-owned EVS prevents one request closing another request's temporal history. Warmup closes its own EVS session on success and failure, leaving the single configured slot available for the first real clip. Alert fixes include schema resource packaging, incident route formatting and blank Elasticsearch host validation.

## Operating the unified checkout

Use `python3 tools/runtime/bootstrap.py` for hardware-aware setup and `python3 tools/runtime/ui.py dev` for source-mounted UI development. See [device setup](../device-setup.md), [runtime tools](../../tools/runtime/README.md) and [UI workflow](../ui-development.md).

On this Spark, the explicit new engine selection is:

```sh
python3 tools/runtime/bootstrap.py render --host-ip 127.0.0.1 --cached-models --rtvi-vlm-image vss-rtvi-vlm:3.3-sbsa-codecs --adaptive-evs --demo-profile clips --no-detector
```

Rendering alone never starts containers. Omitted options preserve the saved reserve and runtime choices. `--no-adaptive-evs` keeps the selected engine while disabling session pruning. `--demo-profile all` restores the configured live-analytics roles; this is not a live-ingestion acceptance receipt.
