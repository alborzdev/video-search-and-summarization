```sh
python3 tools/runtime/bootstrap.py render --host-ip 127.0.0.1 --cached-models --rtvi-vlm-image vss-rtvi-vlm:3.3-sbsa-codecs --adaptive-evs --demo-profile clips --no-detector --vios-streamprocessing-image vss-vios-streamprocessing:3.3-native
```

Rendering alone never starts containers. Omitted options preserve the saved reserve and runtime choices. `--no-adaptive-evs` keeps the selected engine while disabling session pruning. `--demo-profile all` restores the configured live-analytics roles; this is not a live-ingestion acceptance receipt.

The clips profile retains the CPU search consumer: it relays `mdx-embed` to
`mdx-embed-filtered` for Logstash indexing. Only the live alert-candidate consumer
is omitted. The cached Embed runtime receives both `KAFKA_TOPIC=mdx-embed` and
the new `MESSAGE_BUS_TOPIC` setting so published vectors reach this relay.

### Upload completion now waits for search visibility

The fresh-data failure also exposed a UI defect: post-processing acknowledgement was presented as a completed searchable upload. Semantic-profile uploads now keep **Video saved · Search not ready** visible until the existing coverage adapter reports at least one indexed semantic segment for the exact newly saved UUID. UUID is supplied as both identity selectors, and the returned source ID must match. Polls are serialized, cancellation-aware and bounded by a 30-second deadline; nonsemantic profiles do not wait for semantic indexing.

If indexing is delayed, the source remains saved and **Retry indexing** reprocesses that source without uploading a duplicate or deleting footage. Cancellation stops receipt polling. A retry that finishes also drains files queued while it was active. Processing acknowledgement is required before offering retry, preventing a second job while the original completion request is still unacknowledged.
