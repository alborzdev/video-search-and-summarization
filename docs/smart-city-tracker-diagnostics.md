# Native tracker provenance

The native worker exports optional `trackerDiagnostics` on each existing observation. It is enabled automatically in `mv3dt-diagnostic`, or explicitly with `--tracker-diagnostics` in another mode. The normal live demo leaves this export off. No new inference or GPU work is introduced. Production `objects`, boxes, map coordinates, associations, rule inputs and thresholds are unchanged.

The frame identity and clocks belong to the enclosing observation. `sdkFrameNumber`, raw `sdkBufPtsNs` and raw `sdkNtpTimestampNs` retain their SDK values as decimal strings. An absent NTP timestamp is null. These are not independently verified camera exposure timestamps. The native RTSP writer's SEI `timestamp` is sampled at encoded-frame handoff and its `frame_num` is writer-local; neither alone establishes a shared render-frame identity. SEI is not yet parsed into this diagnostic record. An exact access-unit/SEI-to-decoded-frame join remains necessary before claiming that alignment.

Up to 256 raw SDK objects are exported before normal identity/class/box filtering. A frame reports its raw/exported counts and truncation. Colliding SDK IDs remain visible here with `idRejectedAsAmbiguous`; the existing live omission policy still removes all such objects from production observations. Diagnostic objects must never be counted as current road users or supplied to map fusion.

Each record separates `detector_bbox_info`, `tracker_bbox_info`, and `rect_params` into `detectorBboxPx`, `trackerBboxPx`, and `rectBboxPx`. All are scaled into source-image pixels without clipping; invalid/nonpositive boxes become null. A detector box is null when detector confidence does not identify a current observation, rather than presenting retained detection metadata as fresh. Native world feet remain metres; image feet are source-image pixels. Invalid/nonfinite fields become null. Large SDK IDs stay decimal strings. Class IDs retain the SDK's raw integer, including unsupported classes.

This distinction matters because SV3DT can reconstruct full-body boxes, whereas the previous worker exported only post-tracker `rect_params`. A comparison calling that output a raw detector anchor was too strong. The new export allows a same-frame comparison of raw detection, reconstructed track box and native foot without selecting a new production anchor. See [NVIDIA's SV3DT documentation](https://docs.nvidia.com/deepstream/9.2/text/DS_plugin_gst-nvtracker#single-view-3d-tracking).

The schema is `services/rtvi/rt-cv/smart-city/schemas/tracker-diagnostics-v1.schema.json`. `make tracker-diagnostics-test` compiles the production observation callback and runs synthetic CPU metadata through it. Pipe its JSON output to `tests/test_tracker_diagnostics_schema.py` to validate the default-off policy, unchanged production objects, cross-class collisions, separate boxes, scaled feet, raw clock/frame identity, 64-bit IDs, finite/null values and the object bound. This is CPU source validation; no runtime accuracy, synchronization, fusion or FPS result is claimed.
