# Canonical Docker deployment

This is the short operator map for the supported Docker Compose paths. It does
not replace the profile-specific runbooks.

## Choose one entry point

| Device / intent | Entry point |
| --- | --- |
| General NVIDIA GPU (H100, L40S, RTX Pro, or another supported non-Thor profile) | `./deploy/docker/scripts/dev-profile.sh up --profile <base|lvs|search|alerts> --hardware-profile <profile>` |
| Jetson AGX Thor full local appliance | `./deploy/docker/scripts/thor-local.sh up` |
| IGX Thor | Use `dev-profile.sh` with `--hardware-profile IGX-THOR` and a supported `base` or `alerts` profile. `thor-local.sh` deliberately validates an AGX Thor (`aarch64` and a Thor GPU) and is not an IGX entry point. |

The `thor-full` developer profile is an AGX-Thor-only compatibility contract;
the `thor-local.sh` launcher is its canonical operator entry point. Do not
combine `dev-profile.sh` and `thor-local.sh` for one Compose project.

## What belongs where

| Category | Location / rule | May be replaced during setup? |
| --- | --- | --- |
| Source | Checked-in Compose, Dockerfiles, scripts, this document, and `image-compatibility.lock.json` | No; update through review. |
| Generated | `generated.env`, resolved Compose output, and runtime image-ID lock files | Yes; regenerate from the versioned contract. They contain deployment-specific values and are ignored by Git. |
| Persistent | `VSS_DATA_DIR` plus named Docker volumes (indexes, recordings, models, reports) | No; preserve across normal recovery and upgrade work. Back up before intentional migration. |
| Cache | Pulled images, build cache, downloaded model assets, TensorRT engines, and NGC/Hugging Face staging caches | Yes; only after an offline-readiness check and with a connected restage plan. |

## Network boundary

Treat the appliance as a **trusted-LAN, single-node** deployment. The browser
gateway is the only intended LAN-facing entry point; model, broker, database,
MCP, and observability listeners must stay loopback or on Docker's private
bridge. This is not an Internet-facing security posture: place the device
behind a trusted firewall/VPN, restrict the LAN, and run
`./deploy/docker/scripts/thor-local.sh security audit` before connecting it.

## Fresh device, then offline operation

1. While connected, select the entry point above, provide required registry
   credentials through the documented secret mechanism, and stage images,
   model assets, and local derivatives. `thor-local.sh up` performs that
   connected bootstrap for AGX Thor.
2. Run `python3 deploy/docker/scripts/validate_deployment_lock.py` to inspect
   the tracked compatibility inventory. Resolve any `WARN` entries before
   claiming a repeatable supply-chain build; a tag-only image is not immutable.
3. For AGX Thor, run `thor-local.sh verify-offline`, then the documented
   `restart`, `ready`, and `doctor` checks before disconnecting. The runtime
   image-ID lock generated by the launcher is the device-specific offline
   proof; this tracked manifest is intentionally not a substitute for it.
4. Offline recovery must use already staged images and persistent data. Do not
   run pull/build/bootstrap operations while disconnected. Reconnect only for
   a deliberate restage, then repeat the checks.

If `verify-offline` reports a changed image ID or a selected image without a
protected lock, do not proceed to an offline restart. Either restage the
reviewed image set through the connected bootstrap, or—only after independently
accepting every current local image—run `thor-local.sh refresh-runtime` to
record the exact staged IDs and immediately repeat `verify-offline`. Refreshing
the lock is a provenance decision, not a harmless way to silence a check.

`thor-local.sh preflight` also requires the root-owned
`/usr/local/bin/sys-cache-cleaner.sh` loop on this Thor. It manages unified-memory
startup headroom and is not installed as a repository service. Confirm it with
`pgrep -af /usr/local/bin/sys-cache-cleaner.sh`; an operator with host authority
must start it before lifecycle work if it is absent.

## Image inventory and validation

[`image-compatibility.lock.json`](image-compatibility.lock.json) records the
supported Thor/full Compose image declarations, source locations, build inputs,
and known pin status. It contains no invented registry digests. Validate it
without Docker or network access:

```bash
python3 deploy/docker/scripts/validate_deployment_lock.py
python3 -m unittest deploy/docker/tests/test_deployment_lock.py
```

Use `--strict` in CI to make unresolved tag-only and untagged references fail.
