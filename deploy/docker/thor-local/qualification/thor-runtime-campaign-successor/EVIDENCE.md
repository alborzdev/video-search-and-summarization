# Evidence boundary

The package is static composition infrastructure, not runtime evidence.

## What the plan proves

- The campaign contract and all three strict schemas are valid Draft 2020-12
  JSON Schemas.
- Thirty-two direct exact locks plus nine distinct transitive collector and
  model-verifier locks match 41 checked-in source files. They cover the current
  selected overlay, strongest feature receipts, host evidence, official model
  semantic collector, canonical requirements/verifier, and model contract.
- The selected overlay remains exactly ten concrete, Warehouse-free,
  cloud-independent candidates with zero runtime receipts.
- The twelve receipt types, twelve ordered phases, and fifteen capability
  mappings are a closed one-to-one composition contract.

## What a passing check proves

- Every named receipt file was a bounded regular non-symlink under the reviewed
  receipt-set directory and its raw SHA-256 matched before parsing.
- Every receipt independently satisfied the exact schema and contract identity
  frozen for its phase.
- Readiness-only evidence was not accepted as model semantics. The mandatory
  live receipt matched four collector hashes, seven semantic observations,
  exact release/artifact/image/served-model identities, and no-cloud wiring.
- Every later phase and descriptor was bound to the raw semantic model receipt
  digest, so feature receipts cannot be composed without that admission.
- Every receipt identity exposed by its producer matched the campaign's run,
  manifest, fixture, model, and profile pins.
- The integrated Search receipt, rather than the conflicting preprovisioned
  standalone receipt, was used.
- Exact capability mapping and mandatory incomplete blockers were preserved.

The output contains only campaign/manifest/receipt-set/model-receipt digests and
counts. It does not reproduce raw receipts, paths, resource IDs, model payloads,
URLs, or authorization material.

## What remains unproven

The current inputs cannot prove complete parity, and this validator refuses to
say otherwise:

1. The supplied live semantic receipt proves the exact official LLM/VLM pair
   only for its fresh readiness-gated run. The checked-in canonical artifact
   lock remains `incomplete_fail_closed`; staged artifact/readiness state is
   therefore receipt-scoped, not a canonical artifact-lock promotion.
2. The provider-free multi-video result has
   `materialized_video_count=0` and `runtime_evidence=[]`. Its deterministic
   four artifacts are not the Agent receipt's live Markdown/PDF bytes.
3. The Alerts terminal receipt binds the static semantic descriptor but exposes
   no run-namespace hash, served media digest, or fixture-server transcript.
4. The UI receipt binds the two uploaded file digests but omits the RTSP source
   descriptor digest.
5. Official upstream Search support on Thor is absent; a receipt can establish
   behavior only for the repository's custom local adaptation.
6. Candidate validation is not authority admission, canonical evidence
   migration, or promotion.

Consequently `evidence_complete`, `promotion_eligible`, and
`canonical_state_advanced` are always false. Warehouse remains excluded and
no required cloud inference can be represented.
