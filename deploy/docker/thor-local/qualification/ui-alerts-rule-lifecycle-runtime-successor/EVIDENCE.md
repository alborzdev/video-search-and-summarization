# Evidence: rendered Alerts rule lifecycle on Thor

On 2026-08-11, the rebuilt `THOR LOCAL VSS` production UI completed a fresh
headless Chromium run against the live local VSS stack in 48,270 ms.

The browser created one timestamp-namespaced RTSP sensor through Video
Management, selected that friendly sensor from the Alerts catalog, created one
rule, observed the server-generated rule ID and `active` state in both the
rendered table and Alert Bridge inventory, and deleted the rule through the
two-step UI confirmation. It then deleted the sensor through Video Management.

The submitted rule URL was exactly the `/v1/sensor/streams` URL already
registered with RT-VLM, not the different `/v1/live/streams` proxy URL. This
proves the deployed reconciliation fix and preserves the Alert Bridge's stream
identity guard.

The browser produced zero console errors and made zero Agent `/generate`
requests. Both screenshots were hashed and deleted. The run removed two owned
incident documents and five owned VST temporary files generated by the
temporary sensor. Rules, unrelated sensors, both VIOS stream catalogs, and the
RT-VLM stream catalog had identical before/after hashes; no owned active state
or incident artifact remained.

The retained `runtime-receipt.json` is the schema-validated machine evidence.
It intentionally contains only counts, booleans, sanitized route classes, and
SHA-256 digests—no runtime UUID or RTSP URL.
