# Metadata-500 current Synthetic Data successor

This immutable successor compiles a **future receipt-authority oracle document** for the four `synthetic-data-tools` capabilities. It rebases the checked selected-500 document's first 289 rows and policy from the current root oracle registry, preserves the selected 211-row candidate suffix exactly, and then makes only the bounded fields needed for the four Synthetic Data rows executor-ready. Relative to that rebased 500-row baseline, the policy and 496 non-target rows are exact.

The checked output intentionally retains `current_state: open_unexecuted` and `evidence: []`. Its `ledger_binding.runtime_state: passed_current` is the projected final ledger binding that a later reviewed metadata integration must match after a clean target-bound receipt succeeds. This package is not itself runtime evidence and does not mutate a ledger or manifest.

The fixture identity has two layers:

- `fixture.materialization.sha256` is the raw SHA-256 of a checked fixture-manifest JSON file, as required by the oracle validator.
- `generated_input_sha256` inside that manifest is the semantic digest of the tiny inputs generated by the runtime executor.

No Warehouse sample, network, Docker, service, model, credential, or download access is used.
