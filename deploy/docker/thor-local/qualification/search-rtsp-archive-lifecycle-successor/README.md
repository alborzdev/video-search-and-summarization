# Search RTSP archive lifecycle successor

This additive qualification package closes the static executor gap for Search-profile RTSP archive management. `plan` is the default and performs no network, Docker, process, model, or download action. `exercise-http` is separately acknowledgement-gated and is restricted to explicit numeric-loopback HTTP origins plus an exact caller-reviewed numeric local RTSP URL. The RTSP producer may use loopback or a private container/host-gateway address; DNS names, public, link-local, multicast, and unspecified addresses are rejected.

The live candidate derives one run-owned name, fails closed on VST or Elasticsearch name collisions, binds the Agent add response to the same VST sensor ID/name, waits for documents in the fixed embed/behavior/raw indices with complete Elasticsearch accounting, deletes through the Agent, and proves exact plus delayed absence. A separately reviewed unrelated VST/Elasticsearch control projection must remain byte-semantically unchanged.

The emitted receipt contains only hashes, counts, booleans, and bounded accounting. It never includes the RTSP URL, source name, sensor IDs, Elasticsearch sources, credentials, or response bodies. The Warehouse sample bundle is excluded.

No live receipt is checked in and this package is non-promoting. A caller must prepare a control projection JSON conforming to `control.schema.json`, review its raw SHA-256, and pass that digest with the exact RTSP URL digest when authorizing a live run.

Static/fake verification:

```bash
python3 executor.py plan
python3 -m pytest -q tests/test_executor.py
```
